# 메이플스토리 파티 분배 디스코드 봇 (역산 방식)

**ConnectLabs · oh_nightmare · 2025**

메이플스토리 파티 플레이 후 아이템 판매금을 파티원에게 공평하게 분배하는 디스코드 슬래시 커맨드 봇.
**역산 (reverse calculation)** 방식으로 분배자가 1건당 정확히 `P = X/Y` 메소를 지출하도록 송금 금액 `S` 를 자동 계산합니다.

---

## 핵심 모델

```
정산 금액 X (판매금 − 카르마의 가위)
  ÷ 파티원수 Y → 1인당 분배금 P

분배자 (=명령 실행자)
  └ 본인 몫 P 인벤토리에서 그대로 보관 (택배 X · 수수료 X)

다른 파티원 (Y-1명)
  └ 각자 S 메소 수령
  └ S 는 (S + fee(S) = P) 가 되도록 역산
  └ 분배자가 1건당 정확히 P 만큼 지출하도록 보장
```

> **왜 역산인가?**
> 분배자 지갑에 X 메소가 있고 이걸 Y명이 똑같이 P씩 지출(또는 수령)하도록 분배하려 할 때, 송금자가 단순히 `P` 를 입력하면 추가로 `fee(P)` 까지 부담해서 X 를 초과합니다. 그래서 입력 금액 `S` 를 줄여서 `S + fee(S) = P` 가 성립하도록 역산해야 분배자 지갑이 정확히 X 만큼 빠집니다.

---

## 슬래시 명령

### `/분배`

| 옵션 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `아이템명` | String | ✅ | 판매한 아이템 이름 (자유 입력) |
| `판매금` | Integer | ✅ | 거래소 수수료 **제외 후** 실수령 메소 |
| `파티원수` | Integer (1~15) | ✅ | 분배할 파티 인원 수 (분배자 포함) |
| `카르마가위` | Integer | ❌ | 카르마의 가위 구매 비용 (없으면 생략) |

---

## 역산 공식

```
S = (P + C) / (1 + r)
```

`r` (한계세율) · `C` (보정상수) 는 P 가 속한 구간에 따라 결정:

| P 범위 | r | C |
|---|---|---|
| P ≤ 110,000 | 0% | −10,000 |
| 110,000 < P ≤ 1,017,200 | 0.8% | −9,200 |
| 1,017,200 < P ≤ 5,089,200 | 1.8% | +800 |
| 5,089,200 < P ≤ 10,239,200 | 3.0% | +60,800 |
| 10,239,200 < P ≤ 25,839,200 | 4.0% | +160,800 |
| 25,839,200 < P ≤ 104,589,200 | 5.0% | +410,800 |
| P > 104,589,200 | 6.0% | +1,410,800 |

floor 후 정수 보정 (`S + fee(S) ≥ P` 까지 +1) 적용.

### 검증된 계산 예시

| 정산금 X | 인원 Y | P=X/Y | S (역산) | fee(S) | S+fee=P |
|---------|------|-------|----------|--------|---------|
| 5억 | 5 | 1억 | 95,629,334 | 4,370,666 | ✅ |
| 3억 | 6 | 5천만 | 48,010,286 | 1,989,714 | ✅ |
| 1억 | 4 | 2,500만 | 24,193,077 | 806,923 | ✅ |
| 12억 | 3 | 4억 | 378,689,434 | 21,310,566 | ✅ |

## 임베드 출력 예시 (이계의반지 5천만, 6명, 카르마 150만)

```
🍁 [ 이계의반지 ] 판매 수익금 분배

수수료 제외 48,500,000메소 정산 · 6명 분배 (역산 방식)

📊 정산 내역
판매금 (거래소 수수료 제외 후) : 50,000,000메소
카르마의 가위 : -1,500,000메소
━━━━━━━━━━━━━━━━━━━
정산 금액 : 48,500,000메소
÷ 6명 → 1인당 분배금 (P) : 8,083,333메소

🎯 송금 금액 역산
P 구간 : 5,089,200 < P ≤ 10,239,200 → r = 3%, C = +60,800
S = (P + 60,800) ÷ 1.03 → 정수 보정 → 7,906,926메소
검증 : S + fee(S) = 7,906,926 + 176,407 = 8,083,333 = P ✅

🚚 1건당 수수료 산출 (S = 7,906,926메소 기준 · 누진)
• 10만 ~ 100만 : 900,000 × 0.8% = 7,200메소
• 100만 ~ 500만 : 4,000,000 × 1.8% = 72,000메소
• 500만 ~ 1,000만 : 2,906,926 × 3% = 87,207메소
• 기본료 : 10,000메소
━━━━━━━━━━━━━━━━━━━
1건당 수수료 합계 : 176,407메소

📤 분배자 → 다른 파티원 (1건당)
• 📝 택배 입력 금액 (S) : 7,906,926메소  ← 이 값을 택배에 입력
• 💸 분배자 추가 지불 수수료 : 176,407메소
• 💼 분배자 1건당 총 지출 : 8,083,333메소 (= S + fee = P)
• 🎁 받는 사람 수령액 : 7,906,926메소

💰 1인당 최종 수령
• 분배자 (홍길동) : 8,083,333메소 (택배 X · 수수료 0)
• 다른 파티원 (5명) : 각 7,906,926메소

💸 분배자 부담 합계
• 총 택배 수수료 : 176,407 × 5회 = -882,035메소
• 총 지출 : 8,083,333 × 6 = 48,499,998메소 (정산 금액 전부 사용)

📦 분배 내역
• 분배자 (홍길동) : 8,083,333메소
• 파티원 2 : 7,906,926메소
... (5명 전부 동일)
```

## 엣지 케이스

| 상황 | 동작 |
|------|------|
| 분배자 혼자 (Y=1) | 택배 불필요, 정산 금액 전부 본인 수령 |
| 카르마 가위 ≥ 판매금 | 분배 불가 (경고 메시지) |
| 1인당 분배금 P ≤ 10,000 | 택배 기본료조차 못 내므로 송금 불가 (경고) |
| X 가 Y 로 나누어 떨어지지 않음 | 나머지는 버림 처리 (경고 메시지로 안내) |
| P 가 구간 경계에 정확히 걸림 | 정수 보정 루프로 자동 처리 |

## 배포 (요약)

1. 디스코드 개발자 포털 → Application 생성 → Bot 토큰 발급
2. OAuth2 → URL Generator → SCOPES `bot` + `applications.commands`, BOT PERMISSIONS `Send Messages` + `Embed Links` → 서버 초대
3. GitHub 레포에 푸시 (`.env` 절대 금지)
4. Railway → New Project → Deploy from GitHub repo → 레포 선택
5. Variables → `DISCORD_BOT_TOKEN` 등록
6. Deployments 로그에서 `로그인 성공 ... 슬래시 명령어 1개 동기화 완료` 확인
